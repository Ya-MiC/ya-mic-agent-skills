# 1. 投資哲學與決策方式

以《窮查理寶典》式多元思維模型進行判斷：
- 能力圈：不理解的東西不假裝理解。
- 反向思考：先問「它消失後會造成什麼損失」。
- 複利：優先維護會使未來每個項目更快、更好、更可信的資產。
- 槓桿：優先處理能被多個產品、客戶或 Agent 重用的能力。
- 激勵：分析它吸引的是開發者、付費客戶、合作方，還是只吸引無效噪音。
- 機會成本：每一項維護成本都要與「投入智能體核心能力」或「量化研究能力」比較。
- 護城河：區分一般程式碼、可重用流程、專有資料、可信品牌、工作流鎖定、社群與分發能力。
- 道德與聲譽：不以誤導性宣傳、侵犯隱私、規避合規、誘導高風險金融行為或隱瞞 AI 生成內容建立價值。

同時使用瓦格納式的系統化與長期視角：
- 不做碎片化最佳化；優先建立可持續運作的系統。
- 把倉庫看成相互依賴的資產圖譜，而不是孤立專案。
- 讓文件、命名、導航、決策紀錄和商業化假設能被人類與智能體共同理解。
- 對書中概念或引用無法確認時，不得捏造來源；只說明你實際採用的可驗證決策原則。

# 2. 組合的最高層分類

整個 GitHub 組合只允許兩個「主業務面板」：

A. 智能體（AGENT）
B. 量化（QUANT）

這不是技術分類，而是資產與業務分類。

每個 repository 必須獲得以下其中一種歸屬：

1. AGENT-CORE
   智能體系統的核心資產：技能庫、規範、記憶、工作流、Agent runtime、協作框架、總索引。

2. AGENT-PRODUCT
   可交付或可訂閱的智能體產品：審計 SaaS、OCR 服務、工作流產品、企業工具、面向終端使用者的應用。

3. AGENT-LEVERAGE
   可被多個 Agent 或產品重用的槓桿工具：插件、模板、SDK、CLI、自動化腳本、評測工具、部署模板。

4. AGENT-RECORD
   Agent 狀態、遷移記錄、一次性配置、歷史 handover。保留，但不視為主力產品。

5. QUANT-CORE
   原創量化研究、策略框架、資料管線、回測系統、風險系統、交易基礎能力。

6. QUANT-FORK
   Fork 而來的量化倉庫。必須標註上游、授權、採用狀態、修改程度與商業使用限制。
   Fork 不是核心資產，除非已累積顯著原創修改、資料、研究流程或使用者價值。

7. QUANT-RESEARCH
   市場研究、因子研究、策略假設、資料分析、教育或實驗性量化工作。

8. HUMAN-REVIEW
   人類待裁決：不能依現有 metadata、README、檔案結構或 commit 資訊可靠判斷的倉庫。
   這是正式分類，不是垃圾桶。

9. RECORD-ARCHIVE
   個人紀錄、一次性網站、課程作品、歷史實驗、交接文檔、與兩條主業務無直接關係但需要保存的內容。

注意：
- 主業務只有 AGENT 與 QUANT。
- HUMAN-REVIEW 與 RECORD-ARCHIVE 是治理狀態，不是第三項業務。
- 不得因倉庫是私有、舊、空白或名稱奇怪就擅自歸檔；先交由人類裁決。

# 3. 智能體業務的初始判斷

# 4. 量化業務的初始判斷

量化倉庫大多可能是 fork；因此先做來源與風險分流，而非直接包裝成產品。

對每個 QUANT 倉庫，強制記錄：
- 是否 fork。
- 上游 repository、作者、授權條款。
- 是否允許商業使用、再散布或 SaaS 使用。
- 原創修改比例：0%、低、中、高。
- 是否含策略邏輯、資料管線、回測、交易執行、風控或展示功能。
- 是否使用真實資金、券商 API、交易所 API 或敏感憑證。
- 是否存在投資建議、保證收益、回測偏誤、資料洩漏、過擬合或合規風險。
- 是否適合標記為「研究」、「學習」、「內部工具」，而非公開商業產品。

量化業務的優先原則：
- 先建立可重複的研究與風控能力，再談產品化。
- 先驗證資料、回測假設、風險敞口與合規界線，再宣稱策略價值。
- 不允許以歷史回測、AI 生成策略或未經驗證模型暗示未來報酬。
- 若沒有原創資料、可信研究流程或風控系統，Fork 只能視為學習資產。

# 5. 強制量化評分模型

對每一個 repository 計算以下指標，每項 0–10 分。

C = 能力圈分數（Circle of Competence）
P = 複利分數（Compounding）
L = 槓桿與可重用分數（Leverage）
I = 激勵與長期目標一致性（Incentives）
R = 逆轉重要性／消失損失（Reversal Criticality）
M = 護城河分數（Moat）
D = 差異化與原創性（Differentiation）
Q = 文件可理解性與交接品質（Documentation Quality）
E = 道德、隱私、授權與合規分數（Ethics and Compliance）
T = 維護負擔與技術債壓力（Technical Debt；分數越高代表越糟）
U = 不確定性（Uncertainty；分數越高代表越不清楚）

計算：

資產複利分數：
ACS = 0.15C + 0.15P + 0.15L + 0.10I + 0.10R + 0.10M + 0.10D + 0.10Q + 0.05E

治理風險分數：
GRS = 0.45T + 0.35U + 0.20(10 - E)

策略優先級：
SPI = 10 × ACS - 5 × GRS

分級規則：
- SPI ≥ 60：核心投資。主動維護、清楚定位、納入首頁面板。
- 40 ≤ SPI < 60：選擇性投資。補 README、補目標與下一里程碑。
- 20 ≤ SPI < 40：保留型資產。只維護最低限度的可理解性。
- SPI < 20 且 U < 6：紀錄／封存候選。保留但停止追加投入。
- U ≥ 6：強制進入 HUMAN-REVIEW；不得武斷歸類或封存。

Fork 修正公式：
若 repository 是 fork，令 F = ForkPenalty：
- 完全未修改：F = 20
- 少量修改或配置調整：F = 12
- 有中度原創模組或研究流程：F = 6
- 顯著重構、專有資料、原創研究或明確產品整合：F = 0

最終優先級：
FinalSPI = max(0, SPI - F)

說明：
- 分數是強迫思考工具，不是假裝精確。
- 每一個分數都要有一行可檢查的證據。
- 若證據不足，優先提高 U，而不是編造高分。
